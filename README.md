# Mizzle: A Complete Concurrent Incorrectness Logic with Applications to Agentic Bug Certification

This repository accompanies the paper of the same name, available on
[arXiv](https://arxiv.org/abs/2607.11611).

## Overview

Mizzle is an incorrectness program logic.
It is built on top of the Iris framework,
and targets MizzleLang, a low-level description of concurrent OCaml.

**MizzleLang is not original work.** It is a modified copy of ZooLang, from
the [Zoo](https://github.com/clef-men/zoo) project by Clément Allain (ISC
license). Most of `src/lang/`, the program text in `src/stdlib/`, and the
`ocaml2mizzle/` translator (a copy of
[`ocaml2zoo`](https://github.com/clef-men/ocaml2zoo)) are vendored from Zoo.
We renamed them to reflect our changes. `src/VENDORED.md` and
`ocaml2mizzle/VENDORED.md` give the exact upstream commits, which files were
copied, what we changed, and the upstream license.

## Architecture

The Rocq development lies within the `src/` subdirectory.

* `ARCHITECTURE.md` is an LLM-generated file summarizing the repo.
* `dataracebench/` and `linearizable/` contain case studies. Each is split
by who wrote the files:
  * `cases/` is generated by `ocaml2mizzle` from the OCaml sources (see below),
    and never edited by hand.
  * `support/` is hand-written: the import preludes, the axiomatized
    dependencies (`dataracebench/support/drb_axiom.v`), helper lemmas, and the
    proof guide (`PROOF_GUIDE.md`) given to the agent.
  * `solutions/` holds the agent-generated reference proofs, one per case
    (see `replay_all.sh --save-solutions` below). `drb001` is the worked
    example printed in the DRB proof guide and is never replayed.
* `logic/` contains the logic.
* `lib/` contains some Rocq utility files.
* `lang/` contains MizzleLang, our copy of ZooLang (`syntax.v`, `semantics.v`, `instances.v`
and the support files they rest on), the modifications we make to it,
as well as a proof that our semantics corresponds to the original one.
See `src/VENDORED.md` for what is copied from Zoo.
* `ocaml2mizzle/` (outside `src/`) is the OCaml-to-Rocq translator, vendored
from `ocaml2zoo` (see `ocaml2mizzle/VENDORED.md`).
* `pure_logic/` contains details about the pure notion of linearizability.
* `stdlib/` contains a standard library of Mizzle specifications for some OCaml
functions; each file also holds the program text its specifications are
stated about (copied from Zoo's `zoo_std`).
* `test/` contains some tests of Mizzle.

## Usage with `ocaml2mizzle`

* `dataracebench/` is an independent OCaml project, containing translations of some benchmarks from
the [DataRaceBench set](https://github.com/llnl/dataracebench).
* `linearizable/` is an independent OCaml project, containing some standard lock-free data structures,
manually made buggy.

The script `dataracebench/run_tsan.sh` runs the ThreadSanitizer comparison of §5.2.

The `ocaml2mizzle` tool converts OCaml code to the deeply-embedded AST.
It is a modified copy of Zoo's `ocaml2zoo`, vendored in `ocaml2mizzle/` (see `ocaml2mizzle/VENDORED.md`) and built as
part of this dune project, so it always matches the language in `src/lang/`.

We provide the script `./gen_mizzle.sh`, taking either `DRB` or `Lin`
as parameter, running `ocaml2mizzle` on the corresponding project above,
and writing the results to the `src/dataracebench` and `src/linearizable` directories,
respectively. It runs the freshly built in-tree binary, never one on `PATH`.
Axiomatizations of missing dependencies are in `drb_axiom.v`.

The translator emits `Require` commands against `mizzle.lang` / `mizzle.stdlib`
directly, so no post-processing of the generated files is needed; the mapping
of library names onto Rocq logical paths lives in
`ocaml2mizzle/lib/mizzlelang/mizzle.ml` and is steered by the `--rocq-prefix`,
`--rocq-lib` and `--no-types` options that `gen_mizzle.sh` passes.

Note that `--only=cases` translates *every* module of the `cases` library,
including `linearizable/bin/key_buggy_stack.ml` (the paper's key-ideas
example).

## Runs of the Case Studies

Replays of the case studies are run with the `replay.py` script.
The script `replay_all.sh` replays all the cases of one of
`Lin`, `Linheld`, `DRB` or `DRBheld`.
The "families" of bugs are defined by `meta.py`.
You can pretty print these runs with `print_session.py`.
The script `line_numbers.py` computes the min, max and average lines of code
per case of a benchmark (e.g., `line_numbers.py DRBall`).
The script `gen_api_card.py` regenerates the API cards of the proof guides
(`src/*/support/PROOF_GUIDE.md`) given to the agent, from the lemmas tagged
`[[card]]` in the library (`--check` only checks they are up to date).

## Paper–Formalization Correspondence

The lists below link the theorems and formal figures of the paper to their
counterparts in the Rocq development (paths relative to `src/`).

### Theorems, corollaries, and lemmas

* Theorem 4.1 (Soundness): `goal_adequacy` in `logic/adequacy.v` (trace-aware variant: `goal_adequacy_tr`)
* Corollary 2.1 (Soundness for stuckness): `adequacy_stuck` in `logic/adequacy_stuck.v`
* Corollary 2.2 (Soundness for non-linearizability): `mgc_non_lin_adequacy` in `logic/adequacy_lin.v`
* Soundness for races (mentioned in §4.3, not stated in the paper): `goal_race_adequacy` in `logic/race.v`
* Theorem 4.2 (Completeness): `completeness` in `logic/completeness.v`
* Corollary 2.3 (Completeness for stuckness): `completeness_stuck` in `logic/completeness_stuck.v`
* Corollary 2.4 (Completeness for non-linearizability): `completeness_non_linearizable` in `logic/completeness_lin.v`
* Completeness for races (mentioned in §4.4): `completeness_race` in `logic/completeness_race.v`
* Lemma 4.3 (mirror entails witness Stuck): `is_stuck_complete` in `logic/completeness_stuck.v`
* Lemma 4.4 (mirror entails witness Racy): `is_racy_complete` in `logic/completeness_race.v`
* Lemma 4.5 (mirror entails witness NonLinearizable): `is_non_lin_complete` in `logic/completeness_lin.v`

### Formal figures

* Fig. 1 (buggy concurrent stack): buggy Treiber stack, OCaml source `linearizable/bin/key_buggy_stack.ml` (outside `src/`), translation in `linearizable/cases/key_buggy_stack__code.v`
* Fig. 2 (key reasoning rules):
  * M-Assert and AssertStuck: `goal_assert` and `goal_assert_stuck` in `stdlib/assert.v`
  * M-CAS-Succ, M-CAS-Fail, M-Fork: `focused_cas_succ`, `focused_cas_fail`, `focused_fork` in `logic/goal_proof.v`
  * RemainingUpdate: `update_remaining` in `logic/interp.v`
  * M-Conclude: `fulfill` in `logic/goal.v`
* Fig. 3 (rules for non-linearizable traces):
  * model, events, histories: the `model` type class in `pure_logic/linear.v`, traces as tagged events
  * M-Emit and the trace assertion: `Trace`, `goal_emit_call`, `goal_emit_ret` in `logic/most_general_client.v` (`Emit` is a primitive of the language, see `lang/semantics.v`)
  * NonLin: `is_non_lin` in `logic/completeness_lin.v`, `Trace_is_non_lin` in `logic/adequacy_lin.v`
* Fig. 4 (most general client): `most_general_client` in `logic/most_general_client.v`
* Fig. 5 (syntax of MizzleLang): `lang/syntax.v`, a copy of the Zoo development's language; our simplifications live alongside it in `lang/`
* Fig. 6 (semantics), and the in-bounds checks of §A.2 (with their correspondence to Zoo's original semantics): `bound_check` and `silent_step_bc_iff` in `lang/alt_semantics.v`
* Fig. 7 (rules for blocks, loads, and stores): `focused_alloc`, `focused_get_field`, `focused_set_field`, … in `logic/goal_proof.v`; M-Context is `focused_bind`
* Fig. 8 (interp rules): `interp`, `interp_running_exploit`, `interp_get_field`, `interp_get_field_header`, `interp_trace` in `logic/interp.v`
* Fig. 9 (Stuck predicate and stuckness rules): `is_stuck`, `stuck_get_field`, and the other per-primitive `stuck_*` lemmas in `logic/stuck.v`
* Fig. 10 (linearizability as a trace property): `trace_linearizable`, `call_valid`, `per_tag_wellformed` in `pure_logic/linear.v`; decision procedure in `pure_logic/linear_check.v`
* Fig. 11 (LAcc, Acc, Racy, IsRacy): `local_access`, `access`, `racy`, `is_racy_intro` in `logic/race.v`
* Fig. 12 (mirror assertion): `mirror` and `mirror_ok` in `logic/completeness.v`; location renaming in `logic/translate.v`
* Fig. 13 (goal assertion): `goal_pre` and `goal` in `logic/goal.v`
* Fig. 16 (further semantics rules for block construction and compare-and-set): `lang/semantics.v`
* Fig. 17 (spin lock and its specification): `mutex٠create`, `mutex٠lock`, `mutex٠unlock` and `focused_mutex_create`, `focused_mutex_lock`, `focused_mutex_unlock` (M-LockCreate, M-Lock, M-Unlock) in `stdlib/mutex.v`
* §5.2 parallel-for axiom: `drb٠parallel_for` and `parallel_for_spec` in `dataracebench/support/drb_axiom.v`
